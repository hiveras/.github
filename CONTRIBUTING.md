# Contributing to Hiveras projects

Thank you for helping. This guide applies to every public Hiveras repository, unless a repository has its own `CONTRIBUTING.md`.

## Start with an issue

Every change starts as an issue. Please open one before you write code.

- **Found a mistake?** Describe what you saw, what you expected and how to see it again.
- **Have an idea?** Describe the problem it solves and who it helps.
- **Have a question?** Ask it in an issue.

Plain language is welcome, in Dutch or English. You do not need to be a developer. A clear description of the problem is the most useful thing you can give us.

Nederlands is welkom. Beschrijf gewoon wat er gebeurde en wat je had verwacht.

Please do not report security problems in a public issue. See [SECURITY.md](SECURITY.md).

## How a proposal becomes a change

1. **Triage.** We read every issue, ask questions where needed and label it. We aim to let you know whether we take it on, and why if we do not.
2. **Build.** The change is built on its own branch, with automated tests for the new behaviour.
3. **Review.** Every change gets an independent review before it is merged. The review checks that it does what the issue asked, without unwanted side effects.
4. **Tests.** Automated checks must pass. A change with a failing or missing check is not merged.

When the change is merged, we link it from the issue and close the issue.

## Pull requests

Pull requests are welcome for issues we have triaged. Please:

- link the issue the pull request solves;
- keep it small and about one thing;
- add or update tests;
- describe how you checked that it works.

## Privacy

Never include personal data in issues, screenshots, test data or code. This includes names of pupils, customers or colleagues.
